# Dota 复盘发布器

## 目标

把已经完成的单场 Dota 复盘变成一篇适合公开阅读的短文，并通过本机 SSH 发布到 `https://ashfury.cn/dota/`。复盘分析本身由 `dota2-deep-match-review` 负责；本 Skill 只负责整理、脱敏、发布和验收。

本 Skill 的预期用法是：在原复盘会话完成 Markdown 后，由用户新建一个独立会话，选择 `gpt-5.6-luna`、推理强度 `max`，再把 Markdown 路径和 Match ID 交给本 Skill。新会话应把 Markdown 当作已完成的分析结果，不擅自重做整场复盘或改变结论。

## 启动词与触发边界

以下两个启动词都表示进入发布流程：

- `上传复盘`
- `更新网页`

用户可以在新的 Work 或 Chat 会话中直接输入启动词；如果同时写了 Match ID 和 Markdown 文件路径，直接开始。也支持显式写 `$dota2-review-publisher`，但不要求用户记住这个名称。

- 用户明确说“上传复盘”“更新网页”“发布”或“归档到网站”，或在同一条请求中明确要求复盘完成后发布时，才执行外部写入。
- 只有“复盘完成”而没有发布授权时，先生成待发布草稿，不修改服务器。
- 如果收到来自原复盘会话的文件路径和 Match ID，优先读取该文件；不要要求用户把整场原始 JSON 再上传一遍。
- 如果用户要求修改网站结构或视觉设计，先按网站开发任务处理；不要把该任务误判为单篇复盘发布。

## 固定工作流

1. 确认比赛 ID、英雄、胜负、比赛时长和用户玩家位。若用户没有提供完整复盘结论，先使用已有复盘结果；不要凭最终面板臆造具体团战时间点。
2. 读取 [公开摘要模板](references/public-summary-template.md)，生成 `content/reviews/<match_id>.md`。
3. 公开摘要保持短小，必须包含：`一句话结论`、`表现评价`、`对线建议`、`团战建议`、`决策失误`、`下一局行动`。可选加入 `数据说明`。
4. 每一条判断分清：
   - **数据明确显示**：能从比赛解析直接核对的事实；
   - **模型判断**：由多个事实推导出的建议；
   - **未知**：当前数据无法确认的走位、技能目标、冷却或具体责任。
5. 表现好时写出可复用的优点；表现差时直接指出主要责任、不合格环节和后果，不用“发挥一般”掩盖问题。`assessment` 可使用 `good`、`mixed` 或 `poor`。
6. 根据证据添加问题标签；只添加确实成立、对下一局有帮助的标签，不为了凑数量贴标签。可用标签包括：`对线炸裂`、`刷了送`、`刷钱慢`、`买活送`、`省 BKB`，也可以使用同样具体的短标签。没有明显问题时不添加负面标签。
7. 执行脱敏检查：默认不公开账号 ID、玩家真实/游戏昵称、聊天内容、原始 JSON、Replay 文件、内部路径和 SSH 信息。只有用户明确要求时才考虑公开身份信息。
8. 为本篇 Markdown 写入 `published_at`，使用实际上传时间；它是首页排序的唯一依据。不能按比赛时间、文件名或 Match ID 排序。
9. 使用 [索引生成脚本](scripts/build_archive_index.py) 扫描公开 Markdown，生成 `public/reviews/index.json`。生成后确认 JSON 按 `published_at` 从新到旧排列，并包含 `tags`。
10. 使用现有网站模板生成首页卡片和单篇文章页：胜利结果显示绿色，告负结果显示红色；首页展示问题标签。不要改变既有 `/dota2/api/` 与 `/dota2/mcp` 服务。
11. 发布前保存服务器端 Nginx 配置备份；把源文件留在服务器的非公开目录，把网页文件部署到现有 Dota 静态目录。具体路径和命令见 [服务器约定](references/server-contract.md)。
12. 发布前后都检查：Nginx 配置测试成功、Nginx 平滑加载成功、首页返回 200、文章页返回 200、原有 Dota API 仍返回 200。任一步失败就停止，不报告“已发布”。
13. 完成后只向用户报告：文章标题、公开链接、是否通过验收、若有问题的具体原因。

## 文章判断规则

- 不用单一 KDA 宣布“打得好”或“打得差”；至少结合生存、参战、英雄伤害、建筑伤害和资源转化。
- 终局数据只能支持结果层判断；没有时间轴时，不得声称某次进场、技能目标或决策发生在具体分钟。
- “没有记录到”不等于“没有发生”。涉及买活、BKB、技能冷却、视野和目标时，按数据字段的实际覆盖范围表述。
- 公开文章的目标是帮助下一局改进，不是写完整战报。默认控制在一篇短文范围内；只有用户要求深度版本时才扩展关键团战等章节。

## 输出格式

发布成功后使用简洁中文回复，并包含：

- `已发布` 或 `未发布`；
- 文章名称和 Match ID；
- 公开 URL；
- 本次是否保留了“表现差/决策失误”的明确评价；
- 数据不足时说明哪些结论仍待录像确认。
